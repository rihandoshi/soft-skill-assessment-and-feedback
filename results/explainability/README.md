# Explainability results (audio branch)

One folder per stage of `markdown/EXPLAINABILITY_STAGES.md`. Inside every stage folder the same layout:

- `report.md` (or `*_report.md`): generated by the stage script; re-running the script overwrites it.
- `notes.md`: hand-written interpretation (Stages 0 and 3); never overwritten.
- `tables/`: CSV outputs. `plots/`: figures. Stage-specific extras are listed below.

All paths are defined once in `scripts/explainability/paths.py`.

## Results so far

1. Answer **length** is the one delivery behaviour RecruitView raters penalise within the same person; loudness and absolute pitch only identify the speaker or microphone (Stage 0, 3).
2. Every answer has 50+ descriptors; extreme values were checked against Whisper and a second pitch tracker, and seven extraction bugs were fixed (Stage 1).
3. Reference tables are fitted on train participants only and transfer to validation. Every answer gets a hard class in each of the seven audio categories (e.g. Pace: slow / typical / fast; Expressiveness: monotone / typical / highly varied); Pace and Conciseness are used for feedback, the other five are experimental until validated. Active flags: `too_fast`, `long_answer` (Stage 2).
4. The interpretable signals reach ~90% of WavLM's accuracy (~97% with length), but within a person almost nothing besides length holds, because RecruitView's per-answer score differences are mostly rating noise (Stage 3).
5. Verbatim ASR replaced the cleaned transcripts: real sentences instead of subtitle lines, real word counts. Trailing off, measured at real sentence ends, now goes with lower scores within a person (weak); `too_slow` is back as experimental; fillers are handed to the text branch (Stage 4).
6. A pretrained speech-emotion model mostly measures the speaker (87%), cannot separate dominance from arousal (ρ 0.98), and raters score *calmer* speakers as more confident (ρ −0.50 between people). The composure class now describes activation relative to the speaker's usual (Stage 5).
7. Next: quality gate (Stage 6), then MIT validation (Stage 7) and human annotation (Stage 8) decide which experimental categories become feedback.

`stage3_validate_recruitview.py` (~12 min) → `fit_reference_distributions.py` again (it reads Stage 3's decisions).
